# AGENTS.md

This repository builds ECI Live, a daily capability index of AI models scored per variant, published at <https://soffits.github.io/eci-live/>.

It uses Epoch AI's open benchmark data and Epoch's Capabilities Index (ECI) method: the model-level fit runs Epoch's own open-source code (`epoch-research/eci-public`), and each variant (model version: reasoning setting, provider or mode) is then scored on its own results with the fitted benchmark parameters held fixed. Everything runs on a schedule inside public GitHub Actions and is published as a static site. It is our own index: it doesn't compare itself with Epoch's published scores.

## Rules

- Transparency is the point: every published number must be traceable to a public workflow run, the exact input data, and the pinned fitting code. No numbers computed off-CI.
- Use Epoch's fitting code as a pinned dependency; never fork or re-implement the method.
- Credit Epoch AI visibly on the page: the data (CC BY 4.0), the method and eci-public, linked. Say once, in one plain sentence in the About section, that ECI Live is independent and not affiliated with Epoch AI. Don't add an "unofficial" badge or label anywhere else (owner's decision).
- General means all-round: a variant is ranked on it only with enough benchmarks covering every core area (`CORE_AREAS`, from the hub's domain tags). One rule (`web/src/eligibility.ts`) decides eligibility on every board; others are provisional (shown only if picked, styled and tagged, never ranked or counted for #1).
- Repository text is English. Conventional Commits. License: AGPL-3.0-only for code.
- Public author name is Sakina; `soffits` is only the account handle.
- Prefer maintained UI components and libraries over hand-written equivalents. Keep code small, typed, and free of dead code.

## Layout

- `src/eci_live/`: the Python pipeline, a thin layer around `eci`. All tunables (URL, bootstrap count, seed, CI level, resamples, rank minimum, core areas) live in `settings.py`. JSON shapes are `TypedDict`s in `schema.py`, mirrored by hand in `web/src/data.ts`; change both together and bump `SCHEMA_VERSION` if the change breaks old snapshots.
- `uv run eci-live` is the single entry point, locally and in CI. It downloads the zip, skips the fit if the zip's SHA-256 already has a snapshot in `--history`, otherwise fits (`refit.fit`, the model-group fit: the bootstrap runs as `BOOTSTRAP_CHUNKS` calls of eci-public's own `fit_eci_model`, seeds derived from `BOOTSTRAP_SEED` with `numpy.random.SeedSequence`, in a spawn process pool with one BLAS thread per worker, draws concatenated in chunk order; the chunk count is fixed so results don't depend on the runner's cores), scores every variant (`variants.py`: input from `prepare_benchmark_data` with each `model_version` as its own group; then `fold_unrecorded`: a group's top non-pro variant, when it is a labelled effort, borrows its non-pro `_unknown`/`_thinking` siblings' results on benchmarks it has none of its own for (marked `borrowed_from`), and those siblings are no longer variants (`Snapshot.folded`; their old `?m=` slugs redirect via `SiteData.redirects`); capability by `domain.fixed_fit` with the group fit's difficulty and slope; intervals from bootstrap draws x `RESAMPLES_PER_DRAW` resamples; rank stats over all-round variants), writes `snapshots/<id>.json`, and always rewrites `web/public/eci.json` from the snapshots of the current schema. A zip with only an older-schema snapshot is fitted again. It then always rewrites `web/public/models/<slug>.json`, one detail file per variant (`detail.py`, slugs from the model version). These come from the latest snapshot's own input zip (the archived release asset if today's download differs), reusing this run's fit when it made the snapshot, else running only the central fit (no bootstrap), so the fit runs once per job. The run fails with an `::error::` if that fit doesn't reproduce the snapshot's group and variant ECIs. Which raw results entered the fit is read from `prepare_benchmark_data`'s output, never re-derived. In Actions it also sets the `snapshot` step output and a step summary.
- `web/`: Vite + React + Mantine + Recharts + mantine-datatable. It fetches `eci.json` at runtime. Pure rules (such as `generations.ts`, which hides models a newer release of the same lab matches or beats from the default Top 20) have `*.test.ts` files run by Node's built-in `node --test`. Each variant has a detail page at `?m=<slug>` (`ModelPage`, slugs from `SiteData.slugs`), also through nuqs with history push, so it survives a Pages refresh and Back returns to the list; names in the chart, table, timeline and Insights link to it via `ModelLink`. The leaderboard shows each model's default variant (`variants.ts`: highest reasoning effort that qualifies, non-pro first). Variants the user adds (`pick.ts`, `ModelPicker`, the per-row "+N" menu) live in the URL as repeated `?model=<version>` parameters through `nuqs` (`NuqsAdapter` in `main.tsx`), so a view can be shared. Lab colours and logos, top-N and the "new" window are in `web/src/config.ts`. `base` is `/eci-live/` (project page).
- `.github/workflows/publish.yml`: the `build` job (`contents: write`) checks out the `data` branch as a worktree at `history/`, refits, builds the site, commits the new snapshot to `data` and creates release `snapshot-<id>` with the input zip. The `deploy` job (`pages: write`, `id-token: write`) deploys. Scheduled runs with unchanged input don't deploy.
- `.github/workflows/ci.yml`: lint, types, tests and build for both sides.

## Where the look lives (keep library upgrades easy)

Style through the libraries' public surfaces only: the Mantine theme, CSS variables, `defaultProps`, per-instance props or style props, and Recharts props. Don't wrap, fork or re-implement library components, and don't target their internal class names (`.mantine-*`, `.m_*`, `.recharts-*`). Custom components must be thin compositions of library parts.

- `web/src/theme.ts` is the theme layer and the first place to look. `createTheme` holds the fonts, primary colour, radius and component `defaultProps`: Anchor inherits size; Badge, Button, ActionIcon, Chip, TextInput, MultiSelect and SegmentedControl default to an `xl` radius; Tooltip has an arrow; Drawer a `lg` radius. `cssVariablesResolver` sets the body and dimmed colours, the placeholder colour, the page surfaces `--eci-surface` / `--eci-hero-surface`, the background dot colour, the capsule opacity, the estimate-dot ring `--eci-dot-ring` and `--drawer-size-sheet` (so `<Drawer size="sheet">` sizes to its content).
- `web/src/config.ts` holds the data-facing choices: lab colours and logos, weights labels and colours, top-N, page size and the "new" window.
- `web/src/global.css` holds page-level rules only: the cascade-layer order for Mantine and mantine-datatable, `color-scheme` keyed on Mantine's documented `data-mantine-color-scheme` attribute, the body dot grid, the `.num` tabular-figures helper and the one "not selectable" rule for interface chrome: semantic elements (`button`, `label`, `thead`, `header`, `svg`, tooltips, options) plus a `.chrome` class that theme.ts puts on Mantine parts without one (Badge, Pill, Tooltip, SegmentedControl, Progress and RangeSlider labels, the Input wrapper, whose field stays editable). Chart tooltips get `wrapperStyle={{ userSelect: "none" }}`; own chrome elements (the leaderboard key, the filter count) carry `chrome`. Content (table cells, code, links, prose) stays selectable.
- CSS modules (`App.module.css`, `components/*.module.css`) style only this project's own elements: page sections, the hero ring, the chart tick layout, the legend key and the About blocks. They read `--mantine-*` / `--eci-*` variables and never select library internals.
- Recharts customisation is all through documented props: a `tick` render function (a `foreignObject` with Mantine parts), a `shape` render function on a range `Bar` for the CI capsules, `ReferenceArea` with a full-width `shape` for the tie band, a row-period `strokeDasharray` on `CartesianGrid` so phone gridlines skip the names, a `ZAxis` range for dot size, and `LabelList content` for frontier labels.
- Library-part compositions: ModelBadges (Badge + Tooltip), the table CI capsule (Progress.Root and Sections), LabLegend (Chip + ColorSwatch, one chip per colour actually drawn via `legend.ts`, so labs on the grey fallback share an "Other labs" chip), Insights (Progress with `lighten` tints and `Progress.Label`, Group, Text), FilterBar (SegmentedControl, MultiSelect, RangeSlider, Drawer), ModelPicker (MultiSelect with `renderOption`), the "added" mark (Badge + CloseButton) and About (CopyButton, Code). The table is mantine-datatable with only its public props.
- On a Mantine or Recharts major upgrade, check theme.ts first (`extend`/`defaultProps` names, `CSSVariablesResolver`, the Drawer size variable) and then the Recharts render-prop signatures (`TickProps`, `ShapeProps`, `AreaProps` and `LabelProps` in Leaderboard.tsx and Timeline.tsx).

## Maintenance

- **Bumping eci-public** is deliberate: change the commit in `pyproject.toml`, run `uv lock`, run the pipeline locally, and check the step summary and that the scale anchors still resolve. The page reads the commit from the installed package's `direct_url.json`, so there is nothing else to update.
- **Another data source** (for example LLM Stats) would get its own fetcher in `source.py`, pass its rows through `eci.prepare_benchmark_data(extra_scores=...)`, and record its own hash in the snapshot's `input`.
- **New labs**: add a colour and a logo import from `@lobehub/icons-static-svg` in `web/src/config.ts`. Unknown labs fall back to grey with an initial and are listed under "Other labs" in the timeline legend.
- Workflow actions use major-version tags (`actions/checkout@v7`) so they pick up fixes without churn. `astral-sh/setup-uv` publishes no major tags since v8, so it uses its full version tag. `.github/zizmor.yml` allows tag refs for `actions/*` and `astral-sh/*` and requires a hash pin for any other third-party action.
- Local checks: `uv run ruff format --check && uv run ruff check && uv run mypy && uv run pytest`; in `web/`, `npm run check && npm test && npm run build`. Workflows: `actionlint` and `uvx zizmor .github/workflows`.
- Run builds niced on shared machines. The bootstrap uses one worker process per core (`os.process_cpu_count()`), so a full fit takes the whole machine for a short while; the CI step duration is the reference timing. Scripts that call `refit.fit` directly need an `if __name__ == "__main__":` guard (spawn start method).
